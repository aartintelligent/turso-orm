# Performance

turso-orm is a layer over the [`turso`](https://crates.io/crates/turso)
client: every statement it runs, an application could run by hand through
the client alone. The benchmarks measure what that layer costs. Each group
does the same work twice, once through the ORM and once through the raw
client with a hand-written statement and hand-written decoding, against the
same seeded in-memory database, a blog of 1 000 users, 10 000 posts and
50 tags. The last column of every table divides the ORM's time by the raw
client's. That ratio is the number to read: the absolute times belong to
the machine that ran them, the ratio does not.

Two things to know when reading the tables. `ActiveModel::insert` and
`ActiveModel::update` read the stored row back with `RETURNING`, which the
engine prices well above a plain write, so their groups compare against a
raw statement with `RETURNING` too, while `insert/exec` and `update/many`
show the plain path. The `render` tables involve no engine at all: they
time the rendering of a statement through the entity API against the bare
SQL builder.

The pages of this section hold one report per version of `turso`, newest
first. A report is generated by the `Benchmarks` workflow each time a
version of turso-orm is published, so that the page states the measurements
of the released code, by hand from the Actions tab when the engine version
changes between releases, or locally with `just bench-report`; the same
engine version overwrites its page, a new one adds a page. The benchmarks themselves live in the
[`benches/`](https://github.com/aartintelligent/turso-orm/tree/main/benches)
directory of the repository.
